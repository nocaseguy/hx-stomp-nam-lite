# Global Settings [verified on unit]

The setting IDs, the stores behind them and the Globals file, the menu and its pages, and the virtual settings every HXtra feature uses. Status tags as in [conventions.md](../conventions.md).

## Values and IDs

- Global Settings has 6 stock sections; `tools/patch_menu.py` adds a 7th, **"HXtra"**. Entries are identified by a setting ID and carry a label (`b'Section\nName'`), a limits object, and a value-string table.
- Shipped (every feature setting has been a virtual setting since #34, see below; the real IDs here are where they were before): **Tuner Activation** (Hold/Press, ID 29) and **Lock Tuner Settings** (Off/On, ID 104), in HXtra until the [tuner page](../features/tuner-page.md) took them (a feature with `MENU = False` keeps its IDs and limits but gets no HXtra page; with no page left, HXtra is not added); since then they are a switch of their own, `HX_TUNER`, off by default like the others. `HX_DSP_METER` builds add **DSP Disp** (Used/All, Free, Used%; ID 101, which the old `dsp-meter` test images had on 102) on a page of its own.
- **Value strings show 8 characters, on one line** [verified on unit]: longer ones are cut off, and unlike the labels a `\n` does not start a second line.
- `GET_VALUE` at `0x28e1f844` (call as `0x28e1f845`): `(id, out)`, result at `[out+4]`; the buffer must be at least 8 bytes.
- Limits code for an int 0..3: `0x28e1ed1c`.
- `HX_PROBE` reuses IDs 29 and 104 for its knobs and so disables the tuner features. `HX_GR` has no Global Settings: the meter is set by the compressor block's GR knobs. (Earlier GR images used IDs 102, 128 and 126 on a second HXtra page; the main store keeps records for IDs up to `0x88` only, and those three have empty labels, the stock 0..1 limits entry, and no stock reader.)
- **Main store range** [verified offline]: the main store holds IDs 0..`0x88` (137 records). For IDs `0x89..0x95` (137..149) the get (`0x28e1ef64`, `cmp r4,#0x88`), `GET_VALUE`, the store write (`0x28e1f0d8`, `cmp r0,#0x88`), the limits getter `0x28e20280` and the long-label function `0x28d97634` all return -3, checked by emulating them; `NAMES_LONG` has exactly 137 slots, so a label slot above `0x88` overlaps `NAMES_SHORT`. `patch_menu.MAIN_STORE_IDS` still runs to `0x95`; no feature uses a real ID since virtual settings, and the fix (branch `main-store-range`, closed PR #32) can come back if one ever does.
- **IDs** (`tools/setting_ids.py`): one line per ID, with its owner and the settings it held in earlier builds (a unit keeps values by ID). Of the main store's empty-label IDs, only 102, 104, 126 and 128 have the stock 0..1 limits entry; `python3 tools/setting_ids.py free <stock .hxf>` lists the empty-label IDs not yet in the file, with the stock reads and writes found for each. **[verified on unit]** 63, 74, 78, 101, 120 and 132 have no stock read or write and hold their stock limits value (100, 1, 0, 0, 1, 0), so they are spare; 105..116 hold their stock default too (see below). **Persistence [verified on unit]**: in a `--writes pass` run, ID 74 set to 5 (an engine setting with its own limits) and the stock MIDI Thru set to On both survived a power-cycle and a boot of the stock firmware; ID 63 read 100 (its stock value) at the start of that run, so an earlier 3 set on it was lost; it may have been set only in a plain RAM run (`writes: ram`), and was not retested.
- **Out of spare IDs** [verified offline]: after long press, `setting_ids.py free` lists only 21, 28, 85..93 and 100, all with stock reads and writes; 85..93 and 100 are the tuner's own settings (reads `0x28d9188e..0x28d91ab8`, beside the tuner settings handler `0x28d916d4`). Stock IDs for hardware the HX Stomp lacks were a stopgap (breathing line's first builds took Scribble LCD Select 23, Scribble LCD Contrast 24 and RF Channel 121, writing its labels over the stock ones); every feature setting is now virtual (see Virtual settings), and those IDs are stock again. For each of the three: the long and short labels are the same text, `stock_uses` finds no read or write, no halfword ID table in Entry 0 holds it next to a neighbouring ID, and its limits code is an int with default 13, 50 (0..100) and 14. Emulating the store write `0x28e1f0d8` from the stock Entry 0: 6, 7, 23, 24, 72, 121, 122, 130 and 131 store an int; 32 returns -21 and stores nothing (it refuses 32..56 and 105..116), 4, 5 and 8 return -3, so Mic In Gain cannot be a knob.
- **Limits types** [verified offline]: the `movs r3,#type` of an ID's limits code: 1 a bool (XLR Outputs, Thru MIDI, ...), 2 an int (most), 3 a float (BPM, Preset BPM, the Variax knobs, Wireless Gain). Type 3 at `0x28e1ecbc` (IDs 105..116) loads default `0x3f800000` (1.0f) and min 0, so their stored 1.0f reads as a large int; that is why a probe showed them outside 0..254.
- **IDs 105..116** [verified offline]: no stock `GET_VALUE` or setter call names them, directly or through a register. The only code that does is the bulk loop at `0x28de9e5c` (called from the Global Settings menu code at `0x28dcf314` and from `0x28e206b2`, `0x28e207cc`), which reads each ID 1..136 and writes it back through the setter `0x28e1f8f4` (how = 8), skipping 32, 34, 33..56 (the Variax block) and 105..116 (`sub r3,r4,#0x69; cmp r3,#0xb`). **[hypothesis]** they are Variax per-string values (6 Global + 6 Preset, floats defaulting to 1.0), dead on the HX Stomp, which has no VDI port. **[verified on unit]** given int limits (0..4, the engine's snippet), ID 105 shows its default and does not change when its knob turns, so 105..116 are float slots, not spare int IDs.
- **Settings limits for a new range** [verified offline]: a limits snippet stores type `[obj+8]`/`[0x10]`/`[0x18]`/`[0x20]` = 2, default `[0xc]` and `[0x24]`, min `[0x14]`, max `[0x1c]`; the shared tail at `0x28e1ed36` takes type r3, default r2, min r1, max r4. No stock snippet is 0..10 with default 2, and the tbh table (offsets x2 from `0x28e1ebbc`) cannot reach the caves, so GR Size's snippet (12 bytes) sits after the NUL of its own label in the long name table, which is in reach.

## Stores and the Globals file

- **Settings stores and the Globals file** [verified offline]: the main store is IDs 0..`0x88` (40-byte records at `0x2845ee9c + 40 * id`: `{?, id, {type, value} +8, {type, min} +0x10, {type, max} +0x18, {type, default} +0x20}`); IDs `0x96..0xa4` (I/O, 0x2c-byte records at `0x2845e98c`, each set also sent on with a key at +0x1c) and `0xbe..0xcb` (`0x2845ec20`) are two more stores; every other ID up to `0x17d` gets -3 from `GET_VALUE`, the limits getter `0x28e20280`, the class function `0x28e20250` and the long label `0x28d97634`, and nothing from the step `0x28e20158`. The store write `0x28e1f0d8` dispatches on the ID: most copy type and value and set the main store's unsaved byte `0x2845ee90[5]`, but **IDs 32..56 and 105..116 return -21 and store nothing** (checked by emulation, `tests/test_virtual_settings.py`), so ID 32 (Mic In Gain) cannot be an HXtra knob. The save worker `0x28e1ee68` (kicked every 300 ticks by `0x28e1ef18`) writes each unsaved store to the Globals store (sector `0x1ee13`, 8 files of 20 sectors) as msgpack `{key: [{id: value}, ...]}` (`0x28de9748(kind)`, values by their record's type, `0x28de90f0`): file 1 the main store (key 2, all 137), file 0 key 1, file 2 key 0, file 4 key 3, file 5 key 4. At boot (`0x28e2064e`) files 2, 0 and 1 are read back; the main-store branch (`0x28de99a4`) wants exactly 137 elements (else the whole file is dropped) and writes each element's type and value into the records by position, whatever the limits' type. Then the bulk loop `0x28de9e5c` re-applies 1..0x88 through the setter, skipping 32..56 and 105..116. HX Edit's globals message (`0x28e1cb48`) holds the same four stores, the main store through `0x28de967c`: every record, so 105..116 go to HX Edit with their raw values.
- **Virtual settings** (`tools/setting_ids.py` VIRTUAL, `src/m4/virtual_settings.s`) [verified on unit, 2026-11-09, except HX Edit]: settings on IDs `0xcc..0xf9`, which no stock function knows, served by the engine from bit fields of the records of 105..116 (12 x 32 bits). The engine owns `GET_VALUE`, the limits getter, the class function and the long label (exclusive sites, only in builds with a virtual setting), and its HXtra turn and click caves enter `virt_turn` and `virt_click`. A turn runs the stock step arithmetic `0x28dfe6a8` on a record the engine fills, so it feels like any stock knob, writes the field into its container under the store's mutex `0x2845ee88`, sets `0x2845ee90[5]` so the stock save worker writes file 1, and repaints with `0x28dceb30(view, ID)`, as a stock change's message would. A container that is not an int (the 1.0f of a first boot or a reset, or a float a restore could write back) reads as every field's default; the first store writes all the defaults in with it. A stock firmware boot loads the containers as ints, the bulk loop skips them and nothing reads them, so they survive it. Every feature setting is virtual, a container per feature (tuner 105, BPM 106, DSP meter 107, long press 108, breathing line 109), and `test_every_feature_setting_is_virtual` fails on a real ID. A feature that stores a setting itself (the tuner page) calls `hxtra_setting_set`, which sends a virtual ID to the engine's `virt_set` (clamped to max) and any other to the stock setter. **On the unit** (#34 at bb53539 with HX_TUNER, HX_BPM, HX_DSP_METER and HX_LONG_PRESS; payload MD5 `551699a8834b1a19f40e0fd6dd12f796`): the stock Global Settings sections look and turn normally through the owned `GET_VALUE`, limits, class and label. The HXtra settings start on their defaults (BPM 41 Lite / White / Left, FS1..FS5 Hold FS6..FS10, DSP Disp Used/All); one detent is one step, the slot repaints, and a knob press resets to the default. The tuner page's Activate (Press opens the tuner on a TAP press) and Lock (On stops the other tuner settings changing) work, and keep their values when you leave and come back. Long press holds work from their defaults. Persistence: BPM Color Red, FS2 Hold Tuner, DSP Disp Free and tuner Lock On, set in a `--writes pass` run, came back on the next HXtra RAM run after a power-cycle and a boot of the installed firmware, whose Global Settings looked normal. Breathing line's settings (container 109; #33 at 9589819 with HX_BREATHING_LINE, payload MD5 `a577453c68459895b73388e9ebd99bae`, a RAM run): on a never-written container they start on Rainbow, Breathe and 4; Line Color, Line Motion and Line Speed step once a detent and the line follows on Home; a knob press resets to the default; Off gives back the stock line. Their persistence was not tested (a RAM run keeps writes in RAM). **Still to check**: HX Edit shows nothing for 105..116, and an HX Edit backup and restore brings the values back, or leaves them at the defaults.

## The menu

- **The Global Settings menu and a knob turn** [verified offline]: a slot's paint (`0x28dce6e0(view, slot)`) calls the limits getter (its result unchecked), the class function, `GET_VALUE` (no value painted when it fails), `TEXT_FN` and the slider `0x28dfe21c(limits, value, class)`, which for class 0 reads min at +0x14 and max at +0x1c. A turn (`0x28dcef50(view, slot, delta)`, the delta kept in r5) calls the step, which copies the record and runs `0x28dfe6a8(ctx, limits, current, delta, out, class, how = 1)`: a shared count of encoder steps, **4 counts a step** for an int, then clamps to min..max, and calls the setter. The repaint comes from the setter's message: the view's handler takes message type `0x19` with the ID at +8 and calls `0x28dceb30(view, ID)`, which finds the slot showing that ID on the current page and repaints it. A click calls the reset-to-default setter `0x28e1fb7c` and repaints the page with `0x28dce854(view)`.
- **Pages** [verified offline]: the generic category case reads slot `table[page * 3 + slot]` (halfword IDs, `0x17e` = empty), and the per-category array at `0x28e3b588` holds page counts (stock 3, 4, 2, 1, 4, 1); each feature category's entry is the number of its pages.
- **A stock category's page table** [verified offline]: each category has its own table and its own literals (Footswitches, category 2: `0x28e3b550`, `{17, 97, 98, 99, 0x17e, 0x17e}`, Stomp Select and FS3..FS5 Function; loaded from `0x28dce6d4`, `0x28dcedec`, `0x28dcef44`, `0x28dcf134`). The tables sit back to back (`0x28e3b540..0x28e3b5b8`), so one can't grow in place. Nothing derives a later category's pages from an earlier one's count; the save/restore loop `0x28de9e5c` goes by ID. A feature with `MENU = 'Footswitches'` gets a copy of that table, trailing empty slots dropped, its settings after, which the category dispatch caves load for category 2; the stock table and literals stay. **[verified on unit]** (image `cc3b38d4bac6e0496a701ac98dd81c94`, b7823d1): Footswitches shows three pages, FS5 Function / FS1 Hold Function / FS2 Hold Function on page 2 and FS3..FS5 Hold Function on page 3, labels `Function\nFS1 Hold` reading "FS1 Hold" over "Function"; the stock Footswitches settings and the other categories work as before; the release test plan passed on that image.
- **Displays** [verified offline: emulated stock turn]: category 5, one page, table `0x28e3b540` `{25 LED Ring Brightness, 26 Tap Tempo LED, 0x17e}` (literals `0x28dce6c8`, `0x28dcef38`, `0x28dcf128`). `MENU = 'Displays'` fills its empty third slot as `MENU = 'Footswitches'` does Footswitches' (Tap LED Color, [features/tap-color.md](../features/tap-color.md)).
- **Feature categories** [verified offline]: each feature with settings and `MENU` True is a category of its own, 6, 7, … in `ORDER`: its entry in the names list (`0x28e3b5d0`) is its `TITLE`, in the icon list (`0x28e3b5b8`) its `ICON`, in the page counts its pages, and the category dispatch caves load its own page table. Navigation ends at the last of them (`cmp r3,#last` at `0x28dcf162`, `movs r1,#last` at `0x28dcf1a8`). The icon strip scrolls to show it (see Icon strip). This replaced the single HXtra category with a page per feature (PR #38, below), so a feature is a knob turn away instead of a turn and a page press.
- **Icon strip** [verified offline: emulated, built and run on the stock Entry 0; on unit, RAM boot 2026-11-11 with BPM Display and Breathing Line: the carousel turning right and left twice round, the current section lit, leaving Global Settings and coming back, no trails where a narrower icon replaced a wider one]: the view's constructor (`0x28dcf6a8`) makes six image widgets at `view+0x110 + 0x24 * slot`, at x `{9, 57, 111, 161, 214, 263}` (`0x28e3b610`, each slot's left edge), y `0xa6`, anchor 3 (left edge, middle height, so a shorter icon centres itself). Four copies of one loop (`0x28dcf4ee`, `0x28dcf554`, `0x28dcf628`, `0x28dcf67e`, the view in r6) set slot i to `Global_*Sel` (`0x28e3b628`) when i is the current category `view[5]`, else `Global_*` (`0x28e3b5f8`). With feature categories, `patch_menu.py` sends each loop to `src/m4/strip.s`: a carousel over the build's categories (6 plus one per feature section; `STRIP_COUNT` in the generated `strip.inc`), as the menu's navigation already wraps both ways. It keeps the category in its first slot and the one last shown in its own words, and moves only when the current category is not in it: after a step right (the step from the last one, around the carousel, at most half of it) the current one comes in at the last slot, after a step left at the first. From Ins/Outs it is stock; with 8 categories, turning right shows 2..7, 3..8, 4..8 1, … 8 1..5, then 1..6 again. Each icon is moved so its middle is the stock icon's middle in that slot. setImage (`0x10001d14`) and setPos (`0x10001d70`) both go through the node's dirty-rectangle update (`0x10003284`) (a moved icon leaves no trail [verified on unit]). A feature category's dim and lit icons are new images made from its `ICON` as the stock ones relate to theirs [verified offline]: its black border trimmed, 1.6 times the size (each stock strip icon is its section icon at 1.38..1.78 times, by area average), lit with its brightest channel at full, dim that times 0.39 (every stock pair: dim = lit times 0.36..0.44). [verified on unit, RAM boot 2026-11-11: at their section size the icons were too small; scaled, they match the stock ones' size.]
- **Page titles** (PR #38, replaced by feature categories) [verified offline; on unit 2026-11-10, MD5 `9c2c0c13…`: each HXtra page shows its title, the stock sections keep their names, a knob turn leaves the title]: the section paint `0x28dce854(view)` (view `[+0xa]` section, `[+0xb]` page) sets the title with `0x28dc5f20(text)` (`bl` at `0x28dce8e2`, r0 = `names[section]`, r2 the section, r6 the view), which copies at most 64 bytes. Page left/right (`0x28dcf24c`, `0x28dcf278`) store the page and call that paint, so the title is set again on every page turn. `patch_menu.py` owns that `bl` (`p.own_call`) and sends it to a cave that, in section 6, loads `titles[page]` (each feature's `TITLE` on each of its pages), else leaves the stock name. The other paint `0x28dce9b4` (view mode `[+0x44]` 1) still shows `CustomOS`. The section has no page dots; `Breathing Line` (14 characters) leaves room for about 5..10 more [verified on unit].
- **Page icons** (PR #38, replaced by feature categories) [verified offline; on unit 2026-11-10, MD5 `ef642529…`: BPM Display shows `Icon_Tempo`, Breathing Line `Icon_DualIR`, the others `Icon_Displays`, in the stock icon's place]: the same paint shows the section icon with `0x28dc5a6c(image index)` (`bl` at `0x28dce8fa`, r0 = the list at `0x28e3b5b8`, stock `Icon_InsOuts` .. `Icon_Displays`; HXtra's entry is `0x48`, `Icon_Displays`), with r2 and r6 as for the title. `patch_menu.py` owns that `bl` too and gives each page its feature's `ICON` (an Entry 7 record index, from `ICONS`). The section strip at the top is separate: `0x28dcf4d8` draws `Global_*` (`0x28e3b5f8`) and the lit `Global_*Sel` (`0x28e3b628`) for six sections only. `Icon_*Sel` and `Setup_*` are never drawn by Global Settings. `tools/icon_library.py` draws them all from a stock file (`docs/icons.md`).
- **Global EQ** [verified offline]: IDs 190..200 (Low Cut 199, the Low, Mid and High bands 190..198, High Cut 200), from its own page table at `0x28001ec4` (halfword IDs, three to a page, `0x17e` empty) read by the Global EQ view at `0x28d99d48`/`0x28d99e18` as `GET_VALUE(table[page * 3 + slot])`. Views with their own page tables reach settings through a register, which `setting_ids.py free` does not trace.
