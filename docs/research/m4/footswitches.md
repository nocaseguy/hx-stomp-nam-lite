# Footswitches, key events and MIDI CC bypass [verified offline]

Footswitch functions, key events and holds, the event handler, bypass assignment, controllers, and driving a block by MIDI CC. Status tags as in [conventions.md](../conventions.md).

## Functions and events

- **Footswitch functions** [verified offline]: `0x28d9607c()` returns `0x28128a70`; footswitch k's function is the byte at `0x28128a74 + 2k`, and 1 is TAP (the footswitch switch at `0x28dd14e0` reaches the tap call `0x28dd1656` for value 1).
- **Key events** [verified offline]: a ring of `{code, value}` reports (`0x28d9aec4..0x28d9af3c`; not the physical footswitches, see the [probes](../features/long-press.md#probes)) feeds `0x28db90ec(code, down)`. That function posts an 8-byte event `{1, code, -, -, type}` through `0x28db8830`, which calls every listener directly (`blx`, `r0` = event, `r1` = the listener's context) under a lock. So a listener can call another listener with an event it builds itself. Types: 1 press; 2 release; 3 release before a hold (posted right after the 2); 5 hold. Each `down` call adds 10000 µs to the key's counter (`0x281f3d5c + 4 * code`). Above `0xf423f` the function posts type 5 once (hold bits `0x281f3d60`), so **a hold is 1 s, for every key**. A release clears the counter. Codes 9..11 are touches on footswitches 1..3, and codes 12..16 are footswitches 1..5 (index = code - 12; 4 and 5 are the external pair).
- **Raw reports per footswitch** [verified offline]: for codes 12..16 the ring loop asks `0x28dd83c4(0x28d96084(), k)` (byte `[obj + 0x28 + 32k]`, set by `0x28dd83e4(obj, k, v)`, which also sends message `0xc10e`; it is set from preset or editor messages, e.g. `0x28dd4698`). Non-zero: value > `0x3f` is down, else up. Zero: each report gives `down` then `up` at once, so the counter never reaches a hold. The stomp release path reads the same byte as "momentary" (`0x28dd1778`: non-zero toggles the block again on release). **[hypothesis]** It is the stock momentary/latching flag. The physical footswitches do not come through this ring (see the [probes](../features/long-press.md#probes)), so the flag does not stop them making holds.
- **Footswitch event handler** [verified offline]: `0x28dd1978(event, obj)`, registered by the literal `0x28dd293c` (its timer callback is `0x28dd18b0`, literal `0x28dd2950`); obj is `0x28d96084()`. It handles types 1, 2 and 5 only. `[obj + 0x78 + k]` is "footswitch k pressed": a press of code 12..16 sets it and calls `0x28dd14a0(obj, k)` (`0x28dd1b94`), unless setting 21 (`0x15`, footswitch mode) is 2 or 3. A release clears it and calls `0x28dd14a0(obj, k)` again (`0x28dd1b7e`, `0x28dd1e82`, `0x28dd1ea0`). `0x28dd14a0` switches on the function byte (1 TAP, 2 stomp: `0x28dd10c0(obj, k)` toggles footswitch k's blocks on press and, if momentary, again on release). A hold of code 12..16 goes to the TBH at `0x28dd1b60` on functions 1..8: 1 (TAP) gives `0x28dd1e70` (guard `0x28d96134(5)`, then the tuner request `0x28d96588`), and 2 (stomp) gives `0x28dd1e18` (acts only when controller `k + 6`'s byte `0x28de6634` is `0xf` or `0x10`). Function 3 and 4 holds do nothing.
- **The footswitch key task** [verified offline]: footswitch events come from the routine around `0x28db8c20`. It posts whole 8-byte events into a queue with `0x28db88fc` (8 bytes into `0x281f3db0`); `0x28db88a0` drains that queue through the post `0x28db8830`. Each pass adds the time since the last pass (`0x28dadba8`, kept in `0x281f71fc`) to the counter of every key 0..16 whose bit is set in `[0x281f5d98]` and whose hold bit (`0x281f3d60`) is clear (counters `0x281f3d64 + 4k`). Past `0xf423f` it posts type 5 and sets the hold bit. Release (`0x28db8fb6`) posts type 2, then type 3 if no hold fired, and clears the counter and the bits. So **every footswitch makes a hold event after 1 s**, whatever its function.

## Bypass assignment, controllers and MIDI CC

- **Bypass assignment and controllers** [verified offline] (details in the long-press branch's research):
  - Bypass assignment is kept per footswitch list, not per block: list head `0x28d96084() + 0x20 + 32k` (`0x28128b4c`). Each footswitch has 8 nodes of 0x38 bytes at `+0xc0 + 0x1c0k`, and the 40 nodes end exactly at the next object (`0x281294cc`).
  - `0x28dd10c0(0x28128a80, k)` walks that list. The press handler's context is `0x28128a80`.
  - Parameter controllers (`0x28d9608c()` = `0x28125d30`): 0 None, 1-2 EXP1-2, 3-7 FS1-5 (FS k is controller k + 3, `0x28dd1228`), 8 MIDI CC, 9 Snapshot.
  - `0x28d96094()` (`0x281252b8`) is the Command Center: Instant 1-6, FS1-5 (6-10), EXP1-2.
  - The Bypass Assign labels (`0x28e3a190`, 8 pointers) and the knob limits (`0x28dbbef0`) stop at FS5 and EXP toe. A block record restore (`0x28dd45ae`) unassigns a footswitch index above 4.
  - So **there is no room for FS6..FS10**.
  - A MIDI CC bypass assignment is driven by `0x28dde408(0x28125d30, 8, cc, value)`, with value a float (the stock MIDI receive at `0x28d9b90e` passes cc value / 127.0; the footswitch path at `0x28dd123a` passes 0.0 or 1.0).
- **MIDI CC bypass, as the virtual footswitches use it** [verified offline]:
  - **Nodes:** controller nodes are `0x28125d30 + 0xac + 0x48i`, i = 0..63. Fields: +0x44 is 0x40 when free; +0x28 is the kind (2 = bypass); +0x10 is the controller (8 = MIDI CC); +0x14 is the CC; +0x2c is the block. The stock MIDI In lookup `0x28ddebcc` reads them under the controllers' lock (`+4`).
  - **Reading a block's state:** `0x28e04514(0x28d92a98(), block, &out)` sets out to 1 when the block is bypassed. It takes the DSP-model lock itself, and leaves `out` unwritten for an unknown block. The stock toggle at `0x28d9489c` gets the state, then sets the opposite with `0x28e045a0`.
  - **Driving a CC:** `0x28dde408(0x28125d30, 8, cc, value)` drives every assignment on that CC. The value is float bits in r3: below 0.5 bypasses, 1.0 turns the block on. That is the stock MIDI receive's path (`0x28d9b91a`, CC value / 127.0), and the footswitch toggle calls it from the event handler (`0x28dd123a`).
  - **Which CCs:** MIDI receive (`0x28d9b89c`) keeps CC 0..3, 32 and 49..81 for global functions. Every other CC, 102..106 included, goes to `0x28dde408`.

Long press and the virtual footswitches FS6..FS10: [features/long-press.md](../features/long-press.md).
