# Tap LED color (`HX_TAP_COLOR=1`, `tools/features/tap_color.py`, `src/m4/tap_color.s`)

The TAP footswitch's ring, switch icon and label in the colour Global Settings > Displays > Tap LED Color picks. Status tags as in [conventions.md](../conventions.md).

- **Setting** [verified offline: emulated stock turn]: Tap LED Color, virtual ID `0xdf` (container 111, bits 0..3), in Displays' empty third slot under Tap Tempo LED (`MENU = 'Displays'`, so no new page; `patch_menu.STOCK_CATEGORIES` has Displays at category 5, table `0x28e3b540`). Values Red (default, the stock colour), DkOrange, LtOrange, Yellow, Green, Teal, Blue, Violet, Pink, White, Rainbow, Random. Its label is stored `Color\nTap LED`: a two-line label's last line shows on top, so the first build's `Tap LED\nColor` read "Color / Tap LED" [verified on unit, 2026-11-12, demo-videos-4].
- **Palette** [verified offline: the stock functions run in unicorn]: per value, the LED driver's lit colour (`0x28dd8030(_, i, 1)`, i = 2, 3, .., 10, then 1 for White), the label's text colour (the block categories' colours, `0x28e2815c`; White their gray `0xb1b1b1`, as stock labels a white block), and the switch icon `0x28dc6e9c` picks for that colour (`Icon_SwitchRed` .. `Icon_SwitchWhite`). Each LED index is the colour its name says [verified on unit, boot-1].
- **Hooks** (all `own_call`, nobody else's): the stock beat's two internal-clock colour calls `0x28d9bea8`, `0x28d9bf6e` go to `tap_led`; the Home label builder's TAP case `setColor` at `0x28dc7fca`, `0x28dc7fd4` to `tap_text` and `setImage` at `0x28dc8010` to `tap_icon`. The external-clock calls (`0x28d9bed0`, `0x28d9bf7a`, blue) stay stock. A Home paint `chain_ptr` before-handler recolours the TAP labels shown when the setting differs from the one last applied, since leaving Global Settings rebuilds no label.
- **Rainbow and Random** [verified offline]: the beat's call (`tap_led`) moves them on: Rainbow to its next shade of 42, which `tap_color.py` blends (`rainbow()`, into the generated `rainbow.inc`) from Red, DkOrange, Yellow, Green, Blue and Violet, 7 a step, Violet back into Red (LED and label colour each, a byte at a time); Random to a palette colour by xorshift32, seeded once from the µs clock `0x28da6458`, never the one before. The other site, `0x28d9bf2c` (called by the tap core `0x28d9c132`, the footswitch LED refresh `0x28dd0b0e` and `0x28d94e64`), goes to `tap_led_again`, which re-lights the colour last shown. The label and icon are White's. [verified on unit, boot-2] Random, as Rainbow then, changed every beat with no repeat. [verified on unit, `tap-color-3`, payload `8bf71b50c6b5ee61a56cd782941ad891`] Rainbow's 42 shades move smoothly round the wheel; a tap keeps the current colour and the next beat goes on one step; BPM Color Tempo follows it; Random as before.
- **BPM**: its owned LED send counts any non-black colour as lit, so the dot follows a ring of any colour. `tap_now` holds the colour shown (the label palette's, or the ring's current one with Rainbow and Random); `ORDER = 10` builds tap_color before BPM, whose Color Tempo reads it through the generated `tap.inc` (`TAP_NOW`, 0 without tap_color: stock red).
- **Tests**: `tests/test_tap_color.py` (handlers, palette against stock code, build), `tests/test_virtual_settings.py` (a turn on the Displays page steps it through the engine; the stock Displays settings turn as on stock).
- **On the unit** [verified on unit, 2026-11-12, `tap-color boot-1`, HX_TAP_COLOR + HX_BPM, payload MD5 `9ee4c5da0b018cea7151f8219a2c21e9`]: default red as stock; the setting in Displays' third slot steps and resets; each colour's ring matches its name; icon and label take the new colour on return to Home, with no red frame, and keep it across a preset change; Tap Tempo LED Off darkens the ring while the BPM dot blinks; the dot keeps time with a coloured ring; LED Ring Brightness and Tap Tempo LED work as stock. `tap-color boot-2` (payload `c682a69037a43bd9fe33cad559ce7c45`): Random (then named Rainbow) and BPM Color Tempo, fixed and following the ring, passed.
