# Boot picture, text and emoji (`build.py --splash`, `--splash-text`; `tools/features/splash.py`, `tools/patch_splash.py`)

A boot picture of your own, the boot line's text, and colour emoji in it. Status tags as in [conventions.md](../conventions.md).

## The boot picture and text [verified offline]

- **Text**: the boot view copies `   Firmware  ` (`0x28e24d14`, literal `0x28d92930`) into a 48-byte buffer at `0x2811ee38` (`0x28daad94` = strcpy), appends `3.80.0` (`0x28e24d24`, literal `0x28d92938`; `0x28daade8` = strcat), and centres the result with `Icon_Firmware` at y = 29. Each string has that one reference; the two are adjacent, 24 bytes in all. The splash feature (`HX_SPLASH_TEXT`) writes up to 23 characters there and points the appended literal at the text's NUL.
- **Full screen**: the boot view's image name (`0x28e24cf4`, 16 bytes, one reference) becomes `Screen_Boot`, and a 320x240 PNG goes into that image (Entry 8 item 29). Full-screen card image (MD5 `8d7a254bfc03232cd18fb308fe6e224e`, **not yet tested on the unit**); full-screen card + text `HXtra 3.80.0` (MD5 `e3bf46ab7f38351806a2e0b5eee76457`, **verified on unit**: full screen, text over the picture; each glyph of the text is drawn on its own black box).
- **Glyph backgrounds** [verified offline]: a text widget (`[0]` text, `[4]` max length, `[8]`/`[0xc]` position, `[0x18]` font, `[0x1c]` colour, `[0x20]` anchor, `[0x2a]` visible, `[0x2c]` node) is drawn by `0x1000206c`, which calls the app's renderer `0x28db7aa4(fb, text, len, x, y, font, colour, anchor, mode)` with mode 0 (its only caller is the veneer `0x10003530`). Per glyph, mode 0 calls `0x100014cc`, which reads the glyph's columns straight into the framebuffer, black included, then ANDs them with the colour: a black box per glyph. Mode 1 calls `0x10001664`, which reads into a scratch buffer and writes only non-zero pixels. The splash feature owns the renderer's entry (`p.own_entry`, 6 bytes, `sub sp,#8; push.w`) and branches it to a cave that sets mode = 1 (`[sp, #0x10]`) when r1 is the boot view's text buffer `0x2811ee38`, so only that line changes, then to the moved prologue (checked in unicorn on the patched Entry 0, `tests/test_splash.py`). Topographic image (`tools/splash_topo.py`, seed 23, 34 levels; text `HXtra 3.80.0`; MD5 `8711c5c9d5781f3505c85a3b7b0f8d99`, **verified on unit**: the text is drawn on the picture without glyph boxes). Text `HXS OS v0.1`: MD5 `075b965b0f0ca384afaeed817964928e`, **verified on unit**. The same picture and text built through the features engine (`tools/features/splash.py`, after #10): MD5 `941b9aeae5d6ca9cbce1263a96a067f6`, Entries 1..14 and the image name, text and version pointer identical to the build before the port, **not yet tested on the unit**.

## Emoji [verified offline]

- **Emoji, as built** (`HX_SPLASH_TEXT`, `tools/features/splash.py` with `tools/splash_emoji.py`; glyphs through `p.add_glyph`): each emoji (code point plus joiners, modifiers, selectors) takes a free control-code slot of `hx21_regularFont` (0x01..0x1f, not `\n`/`\r`); its picture (a PNG from `HX_SPLASH_GLYPHS`, `build.py --splash-glyph`, else `tools/emoji_png.swift` renders Apple Color Emoji on macOS) is cropped, scaled to 18 px tall (at most 21 wide) in rows 0..17 of the 21 px cell, blended onto black, pure black kept as `0x0001` because 0 is transparent; it is appended to Entry 8 as a new item and the slot set in Entry 7; the boot line's colour literal becomes `0xffffff`. The first prototype grew the item table at `0x18`, which moved every item by 8 bytes per emoji: a RAM run then uploaded ~3.5 MB of Entry 8 (MD5 `53589eb6b825487bcf9fa28dda53efb5`, superseded). Now the new pixels and a copy of the whole item table go after Entry 8's end and the header's count, table offset and size point there; the stock bytes after the 24-byte header are unchanged. Works because the item lookup `0x28db7844` seeks to the header's table offset (`[state+0xc]`, from `0x28db77d4`) + 8 * index and item offsets are absolute; the data offset `[state+0x10]` is not used there. `hxf_ram.py plan`: Entry 8 320 sectors (160 KiB, the Screen_Boot picture plus ~10 KiB), against 7116 before. Image `HXS OS v0.1 🎸` on the topographic picture (MD5 `fae46e6cf5200fc9990f32dd09911258`, **verified on unit**: the emoji, white line and centring work, but red showed as blue). Fixed channels (MD5 `a8c3c7c8331bfb21a2b87315837f5136`, **verified on unit**: red guitar, same background, white centred line without glyph boxes, loading bar; Home, block thumbnails, footswitch/snapshot colours, Global Settings with HXtra, tuner and preset names unchanged; preset load and save work; power-cycle returns to the installed firmware): `tools/splash_topo.py`'s palette has red and blue swapped so the background's bytes stay exactly as shown; a preview composited from that image's own Entries 7 and 8 shows the line in white with the colour guitar.
- **Emoji alignment** [verified on unit]: `hx21_regularFont`'s capitals and digits are rows 1..16 of the cell (baseline 16; x-height from row 5; descenders to 20). Centred in the whole 21 px cell, emoji sat about 2 px below the capitals (T2 colour card `96d40456c30eb122cfeb49f8fa01826b`: colours, four emoji with skin tone and a ZWJ family, a repeated emoji sharing its slot, centring all right). Now 18 px in rows 0..17, 1 px beyond the capitals each way: T2 `0ad33628891c1d9c02523df42fbf5024` (**verified on unit**: the emoji sit level with the capitals), T1 `9628f8bab23105731daec6441ee26b75` (same glyph code, not run). T3, the 320x181 mode with ASCII text (`4a19f162aed465e018c8ee602306c580`, **verified on unit**): picture over the black band, the line in the stock grey, loading bar; Entry 7 untouched.
- **Ported onto the features engine** (emoji inside `tools/features/splash.py`, glyphs through `p.add_glyph`): T2 built that way (MD5 `7512035dd7d7d6b588e5093c9c2b2bdc`) has the unit-verified T2's Entries 7 and 8 byte for byte and the same emoji Entry 0 bytes. Result **[verified on unit]** (RAM run): the boot screen as the verified T2 (colours, the emoji line level with the capitals, white, no glyph boxes, loading bar to the end), then Home; the HXtra page with the tuner settings; preset names and fast browsing, knob values, thumbnails and icons, tuner, preset load and save, audio and HX Edit unchanged; a power-cycle returns to the installed firmware.
- Rejected: more than 128 glyphs (the RAM tables are back to back, the loader copies 0x80); a UTF-8 decoder in the renderer (the renderer, the measurer `0x28db78d8` and strlen are byte based). The line's centring counts the emoji like any glyph [verified offline]: the measurer `0x28db78d8` adds width + spacing (3 px in `hx21_regularFont`) for each byte whose glyph is present (`0x28db741c`: item not `0xffffffff`, width and height not 0). The loader copies Entry 7's table to `base + 4` (spacing word at `base`), so slot c is Entry 7 table + 12c.
