# Tuner page (`HX_TUNER`, `tools/features/tuner.py`, `src/m4/tuner.s`)

Tuner Activation and Lock Tuner Settings on a page of the tuner's own settings view. Status tags as in [conventions.md](../conventions.md).

- **The tuner's settings view** [verified offline] (`tools/features/tuner.py`, `src/m4/tuner.s`): functions turn `0x28d916d4(event, view)`, event `0x28d91760(event, view)`, paint `0x28dcca60(view)`, knob redraw `0x28dccfcc(view, knob)` (the turn's tail), enter `0x28dcd350`; the view is `0x78` bytes, `[view+0x74]` the page (0..3 stock), `[view+0x75]` a full-redraw flag (the header and page dots), and `[view+0x48 + 4 * (page * 3 + knob)]` a stock item's value. Pages are 3 knobs: Output, Refrnc, Type / Trails, Offsets, String 6 / Strings 5..3 / Strings 2, 1 and an empty knob; the byte table `0x28e3b2c4` maps page * 3 + knob to items 0..10 (above 10 is empty), with max, min and default tables at `0x28e3b26c`, `0x28e3b298`, `0x28e3b240`. The paint switches on the page (`cmp r3,#3` at `0x28dcca8e`, tbh at `0x28dcca92`, common end `0x28dccb64`) and paints each page's knobs by hand through widget calls taking the knob first: shown `0x28dc6598`, value text `0x28dc654c` (a C string), position `0x28dc648c` (a float 0..1 in r1), label `0x28dc63d0` (`\n` for two lines), colours `0x28dc6454`, `651c`, `6534`, `6504`, `6568` (0xffffff, 0x6b6b6b, 0x4d4d4d, 0xb1b1b1, 0xb1b1b1 for a knob that turns). The last page is `cmp r3,#2` at `0x28d91784` (next page), the paint and the knob redraw reset pages above 3 (`0x28dcca6c`, `0x28dccfd4`), and `movs r0,#4` at `0x28dccd4c` sets the page dots (`0x28dc6688` divides 320 px by it, so any count works). Knob detents come from `0x28dfe2d8(raw delta)` (a shared accumulator, a step every 4), and the view stores its settings with the setter `0x28e1f8f4(0x28e007ec(), id, {type, -, -, -, value}, 1)`. HXtra adds a fifth page (page 4: Activate, Lock, an empty knob) by those four bytes, a hook on the paint switch and its own turn and press handling. **[verified on unit]** (RAM run, 2026-11-07) last, with the caves hand-assembled in `tuner.py`, and again ported to `src/m4/tuner.s` with every feature built in. It is then shown third: the next- and previous-page cases read the page at `0x28d91780` and `0x28d917c2` and store it after `0x28d917ca`, and the page dots read it at `0x28dccd52`; hooks there turn page 4 into place 2 and pages 2 and 3 into places 3 and 4, and back, so the stock code that looks items up by page keeps its numbers. The third place **[verified on unit]** (RAM run, 2026-11-07: paging both ways, the dots, the knobs, the string offsets after it and Lock). It is third because the user's view is that hardly anyone uses the per-string offsets, so Activate and Lock come before them rather than after them. The port's tap reads Tuner Activation through `hxtra_setting_get` (an unset or stray value is Hold, where the caves read the raw value) and keeps r0-r3 for the tap core.
