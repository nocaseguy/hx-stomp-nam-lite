# DSP meter: experiment log

The DSP meter's images in order, with their MD5s and results. How it works now is in [dsp-meter.md](dsp-meter.md). Status tags as in [conventions.md](../conventions.md).

- **Model browser**: the first browser image drew the number in black on the icon (MD5 `f0852c50…`, `2245572a…` with the boot picture): **invisible on the unit** [verified on unit], since the category icons are thin coloured line art on black. White labels right-aligned at x 57 (`af89176e…` with the boot picture) showed on the unit, the second digit too close to the name [verified on unit]; centred labels (`23a442e2…` with the boot picture) look right [verified on unit].
- **DSP-meter square** image (MD5 `c7bdd4fc3d1a26bdd3ac0bb018a60056`, `HX_DSP_METER=1`): `src/m4/dsp_meter.s` wrapped the Home screen's top-view paint: after the stock paint, it filled a 2x2 red square at the centre of the first visible block slot, straight into the framebuffer, first marking the previously used slot's node dirty when the slot changed. Result **[verified on unit]**: the square shows exactly at the centre of the first block, but on the Home screen; it was meant for the Edit view.
- **Edit-view square** image (MD5 `ef6235cefd64868b8d1c9804c9823a74`): the same hook on the Edit view's top half (`0x28dc27f8`, slots at `+0x4a4`); the Home screen is stock again. Result **[verified on unit]**: the square is dead centre on the first block in every arrangement and position tried.
- **All-blocks squares** image (MD5 `ceac51a36fde41bdeaf22fff6a134b78`): after the stock paint, a 2x2 red square at the centre of every visible slot, with no previous-slot bookkeeping (a slot the stock paint redraws or hides loses its square, so every visible slot gets one each paint). Result **[verified on unit]**: every block centred in all arrangements, but the cursor for placing a block in an empty slot also got a square: it is a visible slot showing image `0x67`, which the table `0x28e3a8c0` gives every state of category 0 (empty) [verified offline]. Category `0x12` slots are shown on either path with their on/off state from elsewhere (`0x28de86c0`); categories 16/17 (images `0xd1`, `0x1f0`, ...) are swapped by `0x28dc14a4`.
- **Block numbers** image (MD5 `e8ea950a6fb5528f309e91e847e42cc2`): slots showing image `0x67` are skipped; every other visible slot shows its number (1, 2, ... left to right over the visible blocks) in black 3x5 digits, drawn pixel by pixel with the ROM fill. Icon sizes come from a resource file at run time (`0x28db74a4`), so the scale is chosen per icon: 2 if the number fits a pixel inside the icon, else 1, else none, so no pixel lands outside the rectangle the icon's redraw erases. Result **[verified on unit]**: cursor unmarked, numbers centred, 2x, renumbered on edits and readable on switched-off blocks; but in move mode the picked-up block's number sat at its bottom.
- **Lifted-number** image (MD5 `55f4cf4c6993d29788bf8cf7e985e488`): the number is centred on the square at the top of the picture (side = the smaller of width and height), i.e. the old centre for square pictures and 6 px higher for the 28x40 ones. Result **[verified on unit]**: the picked-up block's number is centred and follows it.
- Two-digit test (number + 10, not committed) **[verified on unit]**: 11, 12, ... at 2x, centred, also lifted.
- **DSP-percentage** image (MD5 `3c4c6abeec7b0c4b47fd7ea363209d74`): each block showed `(cost + 50) / 100`, with the cost from `0x28e01d50` applied to the DSP model's block record. Result **[verified on unit]**: rendering fine, but most blocks showed 0 and only some amps a value (23): the record's `[0]` is not the kind byte the cost function wants (effects are kinds 1..0x15 in the load descriptor, `0x28df51ba`, while their record `[0]` is evidently 0, which the cost function prices at 0).
- **Block-object cost** image (MD5 `c900864da4748e250de912c11d49d449`): the cost is the block object's own `+0x44`, found from the slot through the record's handle (see [m4/dsp-cost.md](../m4/dsp-cost.md)); the cost function is no longer called. Result **[verified on unit]**: effects show non-zero values, amps 8..37, NAM A2 Lite 23; numbers change with the model and follow blocks on both rows.
- **DSP total** image (MD5 `4cc7765b3ba3bb2fc527650b454e76d7`): the Edit view's top right corner shows the preset's total `[[dsp + 0x43fc] + 0xa88]` (read under the DSP model lock) in white 3x5 glyphs at 2x, right edge x 316, top y 232, as Global Settings > HXtra > DSP Disp says: `62/90` (used/limit), `28` (remaining, 90 - used) or `62%`. The box x 270..316, y 222..232 is cleared to black first each paint, so a shorter value leaves nothing behind. Block numbers and the total share one glyph routine (`put`, glyphs 0..9, `/`, `%`). Result **[verified on unit]**: the setting steps and stops at its ends, the total shows and updates in all three formats without leftovers and clear of the title; but the values were cut off ("Used / Limit" over 8 characters), and the fixed 15% in the numerator made the blocks' numbers not add up to it.
- **Blocks' budget** image (MD5 `2dc3b2d40117806ad3b0828ee380aa3a`): the numerator is the sum of the blocks' rounded per cents over all 16 block records, the denominator what blocks may use, 75 (9000 - 1500); DSP Disp has four values, at most 8 characters a line: `Used /\nLimit` (`47/75`), `Remain` (`28`), `Used\nPercent` (`63%`, of 75) and `Remain\nPercent` (`37%`, 100 less the used per cent). The preset total `0xa88` is no longer read. Result **[verified on unit]**: the numbers add up, `0/75` for an empty preset, all formats update without leftovers; but the two-line values were still cut off.
- **Short-names** image (MD5 `98485171ae10228b67a41e236f127071`): DSP Disp is `Used/All` (`47/75`), `All-Used` (`28`) or `Used%` (`63%`, of 75), limits 0..2. Result **[verified on unit]**: all three read in full and behave as named; `All-Used` was renamed `Free` (75 - used) for clarity.
- **Feature module** image (`dsp-meter-features` `53b000a`, MD5 `b4265c686c2cc7d22f3b6f7a953e3a3c`): the module chained after the Edit paint, DSP Disp on ID 101 on an HXtra page of its own. Result **[verified on unit]**: numbers centred (also in move mode), none on the cursor, updates without leftovers, DSP Disp's page and its three values, the total in each format, the numbers adding up to it, `0/75` for an empty preset, second-row blocks.
- **Text-widget total** image (`dsp-meter-text`, `HX_DSP_METER=1`, MD5 `48ec46ab8a6d88ed4e75e8ec9d260cc4`; the first build, `hx28_lightFont` (the title's second label), white, anchor 8 at (316, 0xea), MD5 `13f91eb7ca0782ea543d86bbf9cff396`; **[verified on unit]**: it works, but the font is too big): the total is a stock text widget of the module's own, as the BPM's, instead of 3x5 glyphs. Now `hx21_regularFont`, white, anchor 8 at (316, 228), so its digits (ink rows 1..16) sit on the title's baseline, y 212 (0xea less the 28 px fonts' ink row 22) [verified offline]. It is made and placed on the first paint (before it has text, so its first erase covers nothing); every paint sets its text and `setVisible(1)`, then erases and draws it under the widget lock, after the stock paint; with no DSP model it is hidden. Widths as measured, with the 3 px trailing spacing [verified offline]: `62/75` 63 px (x 253..316), `100%` 50; a model name (28 Lite from x 69) wider than about 180 px runs under it. The block numbers stay 3x5 glyphs. Result **[verified on unit]** (with BPM, `44daf211…`): a good size for most presets; with a long name the total draws over the title's end, which the user accepted.
