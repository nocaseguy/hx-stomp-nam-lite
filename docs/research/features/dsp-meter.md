# DSP meter (`HX_DSP_METER`, `tools/features/dsp_meter.py`, `src/m4/dsp_meter.s`) [verified on unit]

Each block's DSP cost and the blocks' total in the Edit view, and each model's cost in the model browser. Status tags as in [conventions.md](../conventions.md).

Each block in the Edit view shows its DSP cost in whole per cent, and the top right corner the blocks' total as DSP Disp says. In the model browser, each listed model's cost shows between its icon and its name (`dsp_browser` in `src/m4/dsp_meter.s`, chained after the browser's paint, literal `0x28d96df0`; see [m4/model-browser.md](../m4/model-browser.md)): at the model level only (`view + 0x40` = 2), each visible row's item priced by `0x28e01d50`, in white at scale 2, centred between the row's icon's right edge (from its widget's x, width and anchor) and the names, after the level and length calls and under the widget lock. The names move from x 44 to 60 to make room (the constructor's `movs r3, #0x2c` at `0x28d90f72`, the only write of the name list's x; it moves the category pages' names too). No widget covers the strip between icon and name, so each paint wipes every row's strip in black first, and the first paint at another level wipes them once. `src/m4/dsp_meter.s` is chained (`chain_ptr` on the literal `0x28d96da0`) after the Edit view top half's stock paint `0x28dc27f8`; `tests/test_dsp_meter.py` runs it in unicorn (`tests/m4emu.py`). The images in [dsp-meter-log.md](dsp-meter-log.md) were built on the old `dsp-meter` branch (`HX_DSP_METER=1`, patch_menu.py hooks before the features engine); the feature module's code is theirs, chained instead of calling the stock paint itself.

How it got here, image by image: [dsp-meter-log.md](dsp-meter-log.md). The costs it shows: [m4/dsp-cost.md](../m4/dsp-cost.md).
