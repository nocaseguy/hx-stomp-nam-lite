# BPM on the Home screen (`HX_BPM=1`, `tools/features/bpm.py`, `src/m4/bpm.s`)

The tempo at the top left of the Home screen and a beat dot. Status tags as in [conventions.md](../conventions.md).

The tempo at the top left of the Home screen and a beat dot, all **[verified on unit]** in the pre-port builds of branch `bpm-display` (the last, `91d423d`, image MD5 `dde01ed869450f5a7bd494b44ecf76c9`); the port onto the feature framework keeps the handlers and is **not yet run on the unit**.

- **Settings** (Global Settings > BPM Display since #39, labelled Font over Size, Color and Dot over Position, Font Size then XL 35 Bold, L 41 Lite (the default), M 28 Bold, S 21 Reg; virtual since #34, on these IDs before): **BPM Font** (ID 128) 41 Lite, 35 Bold, 28 Bold, 28 Lite, 21 Bold, 21 Reg; **BPM Color** (126) White, Gray, Red, Orange, Yellow, Green, Cyan, Blue, Purple; **BPM Dot Pos** (102) Left, Right, Both. Value 0 is each default **[verified on unit]**: an ID no stock code writes reads 0 until set (the first BPM image showed nothing as its Position listed Off first).
- **Text**: one text widget, anchor 6 at (2, 238); the whole BPM (the float's bits in integer code, rounded), ` X` while `0x28d9685c()` (the tempo screen's `Extrnl`) is set, none in the digit-only fonts, `--` with no tempo. Every Home paint sets its font, colour, text and `setVisible(1)`, which always marks it dirty, so it is redrawn after any repaint of the Home view (e.g. on returning from Global Settings).
- **Dot**: 30 px, nine nested rectangles whose union is a circle, top at y = 237: Right at x 221..250, between the preset number and the Snapshot icon **[verified on unit]**; Left is it mirrored about x = 160, the preset number's middle (a text widget, 35 Bold, anchor 7 at (160, 237), set up at `0x28dca62c`). Each position has its own rectangles (a move would erase the box spanning both). Lit in the BPM's colour while the TAP footswitch's ring is lit, `0x404040` while not, red from a tap until the ring's next turn. **[verified on unit]** Up to `04374aea…` (#11, #14), the dot froze while no footswitch was TAP (Preset and Snapshot modes). Since then, `bpm_tick` keeps the beat itself in those modes. It continues from the stock beat's last turn (`0x281cd074`, noted at each turn of the TAP ring) with the stock's arithmetic, and takes the period from the tempo at the last paint. After more than a beat with no turn, it starts the beat at the current time. **[verified on unit]** (`0d952818…`, 2026-11-04) The dot carries on without a jump into Preset and Snapshot modes, stays in time with a metronome, follows tempo changes, and starts at boot in those modes. The footswitch LEDs look as on stock.
- **Hooks**: Home constructor `chain_bl` at `0x28d96c44`; Home paint `chain_ptr` at `0x28d96e28` (before: settings, tempo and erase; after: draw); the settings store's write `0x28e1f0d8` (callers `0x28e1f492`, `0x28e1f936`, `0x28e1fbce`) `chain_bl`, a repaint for IDs 14..16; the LED task's sleep `chain_bl` at `0x28db7f44`, which lights the dot as the TAP ring; the two Tap Tempo LED reads `chain_bl`, which keep the real value and return On, so the stock always blinks the ring; the tap core `chain_entry` at `0x28d9bfa8` (red at once); and the LED send `0x28d98f74`, a plain `b.w` to `bpm_ledsend` (its second instruction is PC-relative and the hook changes the colour argument), which notes each ring and sends black for the TAP ring's lit colours while Tap Tempo LED is Off, so the ring stays dark and the dot still blinks **[verified on unit]**.
- **Half-drawn dot with the breathing line** [verified on unit, 2026-11-10]: the dot sometimes shows half the unlit grey, half the lit colour for a frame, only while the breathing line runs (a Home paint every 25 ms). Every paint draws all nine of the dot's rectangles in one colour, so the mixed frame comes after the paint: the GPDMA copy into the next buffer, or the display showing a buffer that is still changing. **Tried and reverted** (not a fix, on images `5cbb4462…` and `e28afd9c…`): holding the dot's repaint 10 ms, then 20 ms, after the last Home paint, with the line counting its 25 ms from any Home paint. **Next**: read the UI loop's show and GPDMA path (`0x28db7fxx..0x28db80e6`, list set up at `0x28db8336`) for whether it waits for the copy or for vertical sync. Shipped as a known issue (user decision).
- **Boot**: at boot two black vertical bars cover the BPM until the next Home paint **[verified on unit]**; the LED task's hook requests a repaint every 20 ms from 1 s to 1.5 s after the first paint. The tempo and dot stay hidden for the first 1 s (`SHOW_MS`) and the breathing line holds still for 2 s (`START_MS`), so the two start a second apart: with both on, the first 1..2 s after boot showed animation glitches (user report, 2026-11-11). **[verified on unit]** (RAM run 2026-11-11, `HX_BPM` and `HX_BREATHING_LINE`, payload MD5 `d7b4b675a2b7ee9aa2e02edce4d2d237`): with the stagger, no glitch at boot. **[hypothesis]** Another view (e.g. the preset number panel of `0x28dca5f0`, painted after the Home view) erases there; the root cause is not found.
- **Tried and dropped**: the dot timed by counting the LED task's turns, then by the microsecond clock (a beat start, 60e6 / BPM µs, a 20 ms flash, a downbeat every BPM Beat + 1 beats in BPM Downbeat's colour, IDs 120 and 132): **[verified on unit]** the user could not sync it with a metronome while the tap LED's blink synced, so the dot now follows the ring. A BPM Position setting (six places) was dropped for the fixed top left.
- **Tests** (`tests/test_bpm.py`): the hooks' stubs and handlers, the stock-byte checks and the sharing with other features (on the stock file); the handlers in unicorn: the text at the tempo range's ends and its rounding, ` X`, no tempo, ring following, a tap's red, the boot repaints, the store-write repaints, the Tap Tempo LED read, the LED send's ring notes and darkening, and the settings' effect on font, colour and dots.

The tempo settings, LEDs and stock beat: [m4/tempo-and-leds.md](../m4/tempo-and-leds.md).
